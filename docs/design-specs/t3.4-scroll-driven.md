# BUILD SPEC — T3.4: CSS scroll-driven migration

## 0. Summary of the design

Two feature areas move from JS to CSS scroll-driven animations behind a single `@supports` guard:

1. **Scroll-position mappings** (`scroll(root)` timelines): signal-rail fill, signal-rail node, circuit background parallax. The `--scrollp` JS write is skipped in supporting engines.
2. **Entrance animations** (`view()` timelines): `.reveal` / `.fade` rise/fade, section-head rule draw, trace-divider path/via/label draw, cert gauge fill. These now also run **with JS disabled** in supporting engines — the D-006 upgrade.

**Stays on JS:** count-up numbers, nav scroll-spy + bottom-of-page force, and the **section-title shimmer**. Shimmer decision: it stays a time-based one-shot triggered by `.in-view`. A `view()`-driven shimmer would be scroll-scrubbed — stopping mid-range freezes a bright gradient band across the title at rest, violating both the "never half-state at rest" rule and the T2.7 one-shot policy. The only CSS alternative (registered-property + style container query relay) is exotic and fragile. Consequence: JS keeps observing **only `.section-head`** in supporting engines; no-JS users get no shimmer (pure decoration — acceptable under D-006).

**Core invariant of the CSS path:** *hidden states live exclusively in `from` keyframes; no static hidden styles.* `animation-fill-mode: both` supplies the pre-entrance hidden state. Therefore:
- Timeline inactive (unscrollable page) → animation not in effect → static styles → **fully visible**. Fail-open by construction.
- `animation: none` (reduced motion) → final state. No per-property cleanup needed.
- Print's existing `animation: none !important` global → final state. **No new print rules required** (verified below).
- Late module load / anchor jump / find-in-page: state is a pure function of scroll position — an element past its range renders final state. **`skip-entrance` is unnecessary and never applied to these elements** (JS stops observing them), and there is no hide-then-replay flash because the CSS hidden state exists from first paint.

**Accepted behavior change (state in commit message):** entrances become *scrubbed and reversible* — scrolling back down past an element replays its entrance, and opening a `<details>` that pushes content below the viewport re-arms those entrances. This is position-deterministic instrument behavior (probe position = displayed state) and is intentional.

**Support matrix assumed (2026-07):**
| Engine | Path |
|---|---|
| Chromium 115+ (Chrome/Edge/Opera/Android) | CSS scroll-driven |
| Safari 26+ (shipped 2025-09, macOS/iOS) | CSS scroll-driven |
| Safari ≤ 18.x | JS path (today's behavior, byte-identical) |
| Firefox stable (flag-gated `layout.css.scroll-driven-animations.enabled`) | JS path |

Detection parity: CSS uses `@supports (animation-timeline: view())`; JS uses `CSS.supports("animation-timeline: view()")` — **the identical query string, one guard for both `view()` and `scroll()` features** (engines shipped them together). No split-brain is possible.

## 1. File: `src/styles/global.css`

### 1.1 Append this block at the **very end of the file** (after the existing `@media (prefers-reduced-motion: reduce)` block — end-of-file position is load-bearing: the neutralizer rules below win equal-specificity ties against the earlier `.js.reveal-ready` rules by source order)

```css
/* =====================================================================
   CSS SCROLL-DRIVEN ANIMATIONS (T3.4)
   Entrances + rail + parallax move off JS onto scroll()/view() timelines.
   They run even with JS disabled — an upgrade to the D-006 contract.
   Contract: hidden states live ONLY in `from` keyframes (fill-mode both).
   Inactive timeline (unscrollable page) or animation:none (reduced motion,
   print) therefore always yields the final, fully-visible state.
   The Layout module feature-detects the SAME query string and skips
   observing these elements, so nothing is ever double-driven.
   NOTE: longhands only — the `animation` shorthand resets
   animation-timeline/animation-range to their initial values.
   ===================================================================== */
@supports (animation-timeline: view()) {

  /* ---- Neutralize the JS-path hidden states (class system goes inert;
         also covers the inactive-timeline fallback: static = visible) ---- */
  .js.reveal-ready :is(.reveal, .fade) { opacity: 1; }
  .js.reveal-ready :is(.reveal, .fade).in-view { animation: none; } /* defense: JS no longer adds .in-view here */
  .js.reveal-ready .section-head .rule { transform: scaleX(1); }
  .section-head .rule { transition: none; }
  .js.reveal-ready .trace-div path { stroke-dashoffset: 0; }
  .js.reveal-ready .trace-div circle { opacity: 1; }
  .js.reveal-ready .trace-div text { opacity: 1; transition: none; }
  .trace-div.in-view path, .trace-div.in-view circle { animation: none; } /* defense, same reason */
  .js.reveal-ready .gauge__fill { width: var(--w); }
  .gauge__fill { transition: none; }
  .cert.in-view .gauge__fill { width: var(--w); }

  /* ---- Entrances: reveal / fade ----
     Range ends at entry 60% so text is never half-transparent at rest;
     --i staggers the start spatially (later siblings start deeper into
     the entry). Invariant: --i must stay <= 6 (start 48% < end 60%);
     current max in markup is 3. */
  .reveal {
    animation-name: rise-in;
    animation-timing-function: var(--ease-out);
    animation-fill-mode: both;
    animation-timeline: view();
    animation-range: entry calc(var(--i, 0) * 8%) entry 60%;
  }
  .fade {
    animation-name: fade-in;
    animation-timing-function: var(--ease-out);
    animation-fill-mode: both;
    animation-timeline: view();
    animation-range: entry calc(var(--i, 0) * 8%) entry 60%;
  }

  /* ---- Section-head rule draw (rule is 1px tall — its own view() range
         would be degenerate; drive it from the head's named timeline) ---- */
  .section-head { view-timeline: --sechead block; }
  .section-head .rule {
    animation-name: rule-draw;
    animation-timing-function: var(--ease-out);
    animation-fill-mode: both;
    animation-timeline: --sechead;
    animation-range: entry 0% entry 60%;
  }
  @keyframes rule-draw { from { transform: scaleX(0); } to { transform: scaleX(1); } }

  /* ---- Trace divider (56px tall — entry range degenerate; use cover
         ranges on the SVG root's named timeline, done well below the
         viewport midpoint) ---- */
  .trace-div { view-timeline: --trace block; }
  .trace-div path {
    animation-name: trace-draw-view;
    animation-timing-function: var(--ease-out);
    animation-fill-mode: both;
    animation-timeline: --trace;
    animation-range: cover 0% cover 30%;
  }
  .trace-div circle {
    animation-name: via-in;
    animation-timing-function: var(--ease-out);
    animation-fill-mode: both;
    animation-timeline: --trace;
    animation-range: cover 22% cover 34%;
  }
  .trace-div text {
    animation-name: fade-in;
    animation-timing-function: var(--ease-out);
    animation-fill-mode: both;
    animation-timeline: --trace;
    animation-range: cover 26% cover 38%;
  }
  @keyframes trace-draw-view { from { stroke-dashoffset: var(--len, 600); } to { stroke-dashoffset: 0; } }

  /* ---- Cert gauge fill (8px tall — drive from the card's timeline;
         scrubbed meter fill, settled by entry 60% of the card) ---- */
  .cert { view-timeline: --cert block; }
  .gauge__fill {
    animation-name: gauge-fill;
    animation-timing-function: var(--ease-out);
    animation-fill-mode: both;
    animation-timeline: --cert;
    animation-range: entry 0% entry 60%;
  }
  @keyframes gauge-fill { from { width: 0; } to { width: var(--w); } }

  /* ---- Signal rail: page-progress mapping, linear by definition.
         scroll(root) explicitly (body's overflow-x:hidden propagates to
         the viewport, but root leaves nothing to resolution rules).
         No min-width media query needed: below 1100px the rail is
         display:none and the animations are moot. ---- */
  .signal-rail__fill {
    animation-name: rail-fill;
    animation-timing-function: linear;
    animation-fill-mode: both;
    animation-timeline: scroll(root block);
  }
  .signal-rail__node {
    animation-name: rail-node;
    animation-timing-function: linear;
    animation-fill-mode: both;
    animation-timeline: scroll(root block);
  }
  @keyframes rail-fill { from { transform: scaleY(0); } to { transform: scaleY(1); } }
  @keyframes rail-node { from { transform: translateY(0); } to { transform: translateY(100vh); } }

  /* ---- Circuit background parallax (same -60px mapping as the JS path) ---- */
  .circuit {
    animation-name: circuit-drift;
    animation-timing-function: linear;
    animation-fill-mode: both;
    animation-timeline: scroll(root block);
  }
  @keyframes circuit-drift { from { transform: translateY(0); } to { transform: translateY(-60px); } }

  /* ---- Reduced motion: the global RM rule zeroes durations, but
         progress-based timelines IGNORE duration — these need animation:none
         explicitly (the shorthand also resets timeline/range, killing them
         completely). Decorative motion dies; static styles are the final
         state by the fill-mode contract above.
         DELIBERATE KEEP: .signal-rail__fill/__node stay animated — the rail
         is a scroll-position indicator (feedback, like a scrollbar thumb),
         matching the JS path, which also keeps updating it under RM. ---- */
  @media (prefers-reduced-motion: reduce) {
    .reveal, .fade,
    .section-head .rule,
    .trace-div path, .trace-div circle, .trace-div text,
    .gauge__fill,
    .circuit {
      animation: none !important;
    }
  }
}
```

### 1.2 No changes to the existing print block — verified sufficient
- `*, *::before, *::after { animation: none !important; }` kills every scroll-driven animation (important beats animations in the cascade), and by the fill-mode contract static styles are final states.
- `.trace-div`, `.signal-rail`, `.circuit` are `display: none` in print; `.gauge__fill` width and reveal opacities are already forced with `!important`.

### 1.3 No changes to the existing reduced-motion block
Its `!important` final-state forces (`.trace-div path { stroke-dashoffset: 0 !important }` etc.) remain correct for the JS path and are harmless in the CSS path; the nested RM block in 1.1 handles the scroll-driven animations (including for **no-JS + RM** users, whom the existing `.js.`-scoped rules never matched).

## 2. File: `src/layouts/Layout.astro` (the client `<script>` module only — no markup changes)

### 2.1 Add the feature detect at the top of the module, directly after the `onMQChange` helper

```ts
// CSS scroll-driven animations (T3.4): when the engine drives entrances and
// the rail itself, this module must not double-drive them. The query string
// is byte-identical to the @supports guard in global.css — one detection,
// no split-brain. scroll() and view() shipped together in every engine.
const sda = typeof CSS !== "undefined" && CSS.supports("animation-timeline: view()");
```

### 2.2 Scroll reveal — change **only** the selector line

```ts
const revealEls = document.querySelectorAll(
  sda ? ".section-head" : ".reveal, .fade, .section-head, .trace-div, .cert"
);
```

Everything downstream stays byte-identical and remains correct:
- In `sda` engines, the observer now exists **solely to fire the shimmer one-shot** (`.section-head.in-view .section-head__title`). The `.in-view` it adds also matches `.section-head.in-view .rule { transform: scaleX(1) }` — a static declaration the running view() animation overrides; harmless.
- `document.documentElement.classList.add("reveal-ready")` still runs (shimmer is gated on `.js.reveal-ready`); the neutralizers in §1.1 make its hidden-state side effects inert.
- The `lateLoad` / `skip-entrance` logic now only ever applies to `.section-head`, where it is still wanted: a late-loading module must not flash a shimmer over an already-read title. For the migrated elements, skip-entrance is obsolete by construction (view() state is position-derived) — no removal needed; the code path simply never touches them.
- The RM change-listener's `revealAll()` likewise only touches section-heads; `skip-entrance` suppresses the shimmer, and the CSS RM blocks handle everything else.

### 2.3 Signal-rail progress — gate the property write, keep the listener

Replace the `--scrollp` write inside `updateScrollProgress`:

```ts
if (!sda) document.documentElement.style.setProperty("--scrollp", String(p));
```

Do **not** remove the listener, the rAF coalescing, the `resize` hookup, or the initial call: the same handler owns the bottom-of-page scroll-spy force (`#contact` aria-current), which stays JS in both paths. In `sda` engines the handler degrades to a cheap comparison per frame.

Optional micro-tightening (allowed, not required): when `sda`, skip computing `max`/`p` and run only the bottom-check. If done, keep the `p` computation inside the `!sda` branch.

### 2.4 `--scrollp` lifecycle — resolved
- **Non-supporting engines:** unchanged — JS writes `--scrollp`; the base declarations `transform: scaleY(var(--scrollp, 0))`, `translateY(calc(var(--scrollp, 0) * 100vh))`, `translateY(calc(var(--scrollp, 0) * -60px))` keep working. **Keep all three base declarations exactly as they are** — they are the fallback path *and* the inactive-timeline static state (`--scrollp` unset → `0` → empty rail / node at top / no parallax, which is correct when the page cannot scroll).
- **Supporting engines:** `--scrollp` is never written; the animations own the transforms whenever the root is scrollable. The variable is not removed from CSS.

### 2.5 Everything else in the module is untouched
Counters (JS per task), nav scroll-spy (aria-current requires JS), copy buttons, menu, cursor/magnetic effects, print handlers, hero underline draw (load-triggered, not scroll-triggered — out of scope).

## 4. A11y treatment

- **Reduced motion:** decorative scroll-driven motion (`reveals`, rule draw, trace draw, gauge scrub, circuit parallax) is killed with `animation: none !important` inside the guard (§1.1 nested block) — required because the global RM duration-zeroing rule cannot touch progress-based timelines. Final states render via static styles. The **signal rail keeps moving under RM** in both paths: it is a scroll-position indicator (feedback), consistent with today's JS behavior, `aria-hidden`, and linear-mapped (no vestibular-trigger easing or parallax).
- Live OS toggle to RM mid-session: pure CSS media query — instant, no JS needed for the migrated elements; the existing `rmQuery` listener still handles the JS-only leftovers (shimmer, counters, cursor effects).
- No ARIA changes: all migrated elements are decorative or already-visible content; `aria-current` scroll-spy stays JS-owned. Keyboard focus jumps and find-in-page can never land on invisible content: any scroll the browser performs advances the timelines synchronously.
- Forced-colors: unaffected (entrances animate opacity/transform only; the existing forced-colors title rule stands).

| Engine | JS off — before | JS off — after |
|---|---|---|
| Non-supporting | static, fully visible | identical (unchanged) |
| Supporting | static, fully visible | full entrance motion, rail progress, parallax — designed, not fail-open |

## 6. Edge cases & invariants

1. **`animation` shorthand resets `animation-timeline`/`animation-range`** — the spec uses longhands exclusively inside the guard; any future edit must keep timeline/range *after* any shorthand. Add this as a CSS comment (included in §1.1 header).
2. **Unscrollable page** (huge viewport/zoom-out): timelines inactive → animations not in effect → static visible states. Verified fail-open for all ten migrated selectors.
3. **`body { overflow-x: hidden }`**: body's overflow propagates to the viewport (html has `overflow: visible`), so body is *not* a scroll container and `view()` resolves to the viewport. Rail/circuit use explicit `scroll(root block)` regardless. Do not ever set `overflow` on `html` without revisiting this.
4. **Stagger invariant:** `--i ≤ 6` (range start `48% < 60%` end). Current maximum in markup is 3 (stats/grid `%4`, skills `%3`). Note added where `--i` ranges are computed if desired, but no code change required.
5. **Elements straddling the viewport bottom at load** render mid-range (partially transparent) until scrolled — bounded by the entry-60% cap and only ever at the screen's bottom edge; elements fully inside the viewport at load are past `entry 100%` → final state.
6. **Reversibility / layout shifts:** `<details>` opening pushes content below the fold back to its `from` state; scrolling up re-hides bottom-exited elements. Intentional (see §0).
7. **SVG children with `animation-timeline`:** `path`/`circle`/`text` reference the named `--trace` timeline declared on the SVG root (an HTML-embedded box) — this avoids per-child anonymous `view()` on SVG geometry. QA must confirm the draw in both Chromium and Safari 26 (checklist below).
8. **Cascade defense:** if any future code adds `.in-view` to a migrated element in a supporting engine, the two defensive `animation: none` rules in §1.1 prevent the time-based entrance from double-firing.
