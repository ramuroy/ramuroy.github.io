## 0. TL;DR

The site is in genuinely good shape structurally — the 2026-07-13 hardening pass left it with a clean data model, a real progressive-enhancement contract, a strict CSP, self-hosted fonts, passing build gates, and excellent color-contrast discipline. This audit found **no broken links, no false claims, no build failures**.

What it did find, in order of importance:

1. **Real, user-visible bugs** — the site's own CSP *blocks the boot intro entirely in production* (unhashed inline script); the nav scroll-spy highlight has *never rendered* (CSS/JS attribute mismatch); card hover animations snap instead of animating (a regression from the tilt-removal commit); the page prints as near-invisible light-gray-on-white; the nav clips its links at iPad-portrait widths (721–820 px); the mobile nav is unusable without JavaScript; double-clicking a copy button wedges it on "copied ✓"; touch devices get stuck hover states; and section headings vanish in Windows High Contrast mode.
2. **A motion system with strong ideas but weak discipline** — seven infinite looping animations run simultaneously forever; durations/easings are scattered off-token; entrances, hovers, and state changes are inconsistent across similar components; and a few enhancements (name scramble, count-up zeroing, canvas resize) misbehave in specific, fixable ways.
3. **A content/presentation gap that matters to recruiters more than any animation** — the strongest facts (production safety system at Tata Steel, custom Linux distro, fully on-device voice) are buried below vanity stats and a thrice-repeated identity block; projects list platforms instead of measured outcomes; the two closed-source flagships offer no verifiable artifact.
4. **A long tail of polish opportunities** — SEO metadata trims, font loading, print-as-datasheet, dead tokens, and a ranked roadmap of enhancements that would make the site read as a precision instrument rather than a themed template.

Nothing here requires a rewrite. The fixes are surgical, and the roadmap is deliberately ordered so the highest-leverage items are the smallest diffs.

## 3. Defects

Curated and deduplicated across all audit passes. Every item was verified against the code. Ordered by user impact within each priority band. File references are to the current branch.

### P1 — Real bugs users hit today

**B1. Nav scroll-spy highlight has never worked** ✔
`src/layouts/Layout.astro:135` sets `aria-current="location"`, but `src/styles/global.css:217-218` styles `.nav__link[aria-current="true"]`. The selector can never match, so the active-section color + underline never render — the entire scroll-spy feature (observer, bottom-of-page special case) runs for nothing. Three independent audit passes converged on this.
**Fix:** target `[aria-current="location"]` (or just `[aria-current]`) in both rules; add an active style for the mobile menu too, since `.nav__link::after` is `display:none` under 720 px (`global.css:226`). While in there: the spy also never *clears* the highlight when scrolling back up into the hero ✔ — remove `aria-current` when no section is intersecting.

**B2. Card hover animations snap — a live regression** ✔
`.js.reveal-ready .fade { transition: opacity … }` (`global.css:102`) out-specifies `.pcard`'s and `.gcard`'s own `transition` lists (`global.css:298,330`), replacing them entirely. Result: with JS enabled (i.e., for everyone), hover lift/border/shadow on every project card **jumps instantly with no animation** — while buttons and badges around them animate smoothly. Git archaeology: introduced by `a65464e` ("switch cards to opacity-only entrance") to fix a tilt conflict; the tilt was later removed (`558f9a9`), leaving only the regression.
**Fix:** include the full transition list in the `.fade` rule (`transition: opacity …, transform …, border-color …, box-shadow …`) or scope the entrance transition with `@starting-style`/animation instead of hijacking `transition`.

**B3. Printing produces near-invisible text** ✔
`@media print` (`global.css:500-508`) sets `body { color:#111; background:#fff }` but every component still reads its color from dark-theme tokens (`--text: #E6EDF3`, `--text-secondary: #A9B6C2`, …) — near-white text on white paper. Recruiters print portfolios. Compounding: flagship highlight bullets hide inside closed `<details>` ✔, cert gauge fills are background-gradients that don't print ✔, link URLs aren't revealed ✔, and `break-inside: avoid` on entire sections forces blank gaps ✔.
**Fix:** re-declare the core tokens inside `@media print` (`:root { --bg:#fff; --text:#111; --text-secondary:#333; --muted:#555; --accent:#000; --border:#999; --surface:#fff; … }`) so every component follows automatically; force `details > ul { display:block }`; add `a[href^="http"]::after { content: " (" attr(href) ")" }` for reference links; drop section-level `break-inside`. (The roadmap's "print as a datasheet" item in §10 builds on this fix.)

**B4. Nav bar overflows between 721–820 px (includes iPad portrait, 768 px)** ✔
Masthead (~230 px, `white-space: nowrap`) + 6 nav links + `--space-5` gaps + gutters ≈ 790–800 px required width, but the mobile menu only activates at ≤720 px (`global.css:221`). In the 721–820 px band links clip/overflow.
**Fix:** raise the mobile-menu breakpoint to ~840 px, or shrink `--space-5` gap and hide `.rev` earlier. Align the JS `matchMedia("(min-width: 721px)")` (`Layout.astro:249`) with whatever value is chosen — and derive both from one place if possible.

**B5. Touch devices get stuck hover states** ✔
No hover work is gated behind `@media (hover: hover)`. On phones/tablets, tapping a card applies `.pcard:hover`/`.gcard:hover` lift + glow + spotlight and it **stays stuck** until tapping elsewhere; the magnetic-button and spotlight listeners are gated by `pointer: fine` in JS, but all CSS hover effects are not.
**Fix:** wrap hover-lift/glow rules in `@media (hover: hover) and (pointer: fine)`.

**B6. Entrance-reveal flash on slow connections** ✔
Reveal gating (`reveal-ready`) is added by the *deferred external module* (`Layout.astro:107`). Until it executes, all content is correctly visible; when it runs, above-fold content that was already painted **fades out and replays its entrance** (opacity 0 → transition back in). On fast connections it's a subtle flash; on slow ones the page visibly blinks seconds after render.
**Fix:** either add the gate before first paint for above-fold content (tiny inline script marking `reveal-ready` synchronously with the IO setup inline), or skip the entrance for elements already in the viewport at observe-time (check `el.getBoundingClientRect().top < innerHeight` before adding the hidden state — reveal only below-fold elements).

**B7. Stat counters visibly flash to 0 (and can strand at 0)** ✔
`Layout.astro:329-331` zeroes the server-rendered stat/gauge numbers the moment the module runs, then waits for an IntersectionObserver at `threshold: 0.6` to count up. Users see real values → "0" → count-up (and layout shifts, since "19" → "0" changes width). If a stat element never reaches 60 % visibility (200 % zoom, short landscape viewports), it stays **0 forever** — worse than no JS at all.
**Fix:** don't pre-zero; zero only inside the IO callback right before `runCount` (or better: animate from the real value using `steps()`/CSS, or lower threshold to ~0.2 with `rootMargin`).

**B8. Hero constellation misbehaves on real devices** ✔
Three verified issues in `Hero.astro`: (a) `resize()` re-randomizes every node (`:94-100`) — on mobile, the URL-bar show/hide fires `resize` during normal scrolling, so the constellation visibly teleports; (b) physics are per-frame not per-time (`:90,109`) — the animation runs 2–4× faster on 120/144 Hz displays; (c) the rAF loop starts behind the opaque boot overlay, burning ~1.6 s of O(n²) frames nobody sees.
**Fix:** preserve node positions on resize (rescale by new/old dimensions); multiply velocities by `dt` from the rAF timestamp; start the loop on `rr:boot-done` when the boot overlay is active; consider pausing via `document.visibilitychange` too. Also re-read `devicePixelRatio` inside `resize()` — it's captured once, so dragging the window across monitors with different DPR renders blurry or over-dense ✔.

**B9. BootIntro dialog isn't a real modal** ✔ *(a11y)*
`role="dialog" aria-modal="true"` (`BootIntro.astro:4`) but focus is not trapped and the background is not `inert` — Tab moves focus into the page *behind* the overlay; Escape only works while focus is inside the dialog. Auto-dismiss at 1.3 s limits exposure, but keyboard/SR users can land in a void.
**Fix:** either make it honest (trap Tab between skip button / nothing else, set `inert` on `main`/`nav` while active) or downgrade semantics to a non-modal `role="status"` overlay with the skip button — simpler and arguably more accurate for a 1.3 s splash.

**B10. Name scramble jitters the h1 and spams screen readers** ✔
The scramble (`Hero.astro:156-187`) rewrites `textContent` of the live `<h1>` every 42 ms with random proportional-width glyphs inside `white-space: nowrap` — the heading (and the trailing accent dot) visibly shifts horizontally during the effect, and the accessible name churns.
**Fix:** run the scramble in an `aria-hidden` visual span with the real name in a visually-hidden sibling (stable accessible name); use a mono font or `ch`-locked width for the scramble span to kill the jitter (JetBrains Mono is already loaded).

**B11. Mobile nav is unusable without JavaScript** ✔ *(violates the site's own no-JS contract)*
Under 720 px, `.nav__links` is hidden unconditionally (`global.css:223` — `opacity:0; visibility:hidden; pointer-events:none`) and only JS toggles `data-open`. With JS off/failed, a phone user has **no navigation at all** — on a site whose D-006 decision promises full no-JS function. Desktop is fine.
**Fix:** gate the hidden state behind `.js` (`html:not(.js) .nav__links { position:static; opacity:1; visibility:visible; … }` renders the links as a static column), or move to a CSS-only disclosure pattern.

**B12. Section headings are invisible in Windows High Contrast mode** ✔
The shimmer treatment (`global.css:483`) sets `-webkit-text-fill-color: transparent` + `background-clip: text`; forced-colors mode strips backgrounds but keeps the transparent fill — every `h2` disappears (WCAG 1.4.1-adjacent, real Windows-user impact).
**Fix:** `@media (forced-colors: active) { .section-head__title { background: none; -webkit-text-fill-color: currentColor; animation: none; } }` — same override shape the reduced-motion block already uses.

**B13. Double-clicking a copy button sticks it on "copied ✓" forever** ✔
`Layout.astro:205` captures `const prev = btn.textContent` on every click. Click twice within the 1.4 s window and the second click captures "copied ✓" as the restore value — the button (and its `aria-label`) stays "copied ✓" permanently.
**Fix:** capture the original label once (e.g. `btn.dataset.label ??= btn.textContent` and always restore from `dataset.label`), or ignore clicks while `copied` class is present.

**B14. The site's own CSP kills the boot intro in production** ✔ *(verified by direct hash computation)*
Astro's CSP feature hashes *processed* `<script>` tags but not `is:inline` ones. The emitted CSP meta allows 7 hashes; the BootIntro inline script's actual sha256 (`HkEC0mgz…`) is **not among them**, and the script sits after the CSP meta in the document — every enforcing browser refuses to run it. Net effect: **the first-visit boot intro never runs in production builds of this branch.** Worse, the head script that adds the `js` class is *also* unhashed and only executes because it happens to be parsed *before* the injected CSP meta — pure ordering luck; if Astro ever injects the meta earlier, the entire reveal/enhancement layer dies with it. `check-build.mjs` only asserts the CSP meta *exists*, so the verify gate can't catch this class of bug. Related fragility: `Astro.csp?.insertDirective` is optional-chained behind `@ts-expect-error` (`Layout.astro:10-11`) — if the untyped API changes, `style-src-attr` silently vanishes and every style-attribute CSS variable (gauge widths, staggers, boot delays) gets blocked too; and the `@ts-expect-error` itself will hard-fail `astro check` the day Astro *does* type that directive.
**Fix:** register both inline scripts' hashes via the CSP config (`scriptDirective.hashes`) or `Astro.csp.insertScriptHash(...)`, or convert them to processed scripts Astro hashes automatically (the boot script needs `document.currentScript` replaced with an id lookup). Then extend `check-build.mjs` to compute the sha256 of every inline script in `dist/index.html` and assert each appears in the CSP meta — turning this whole bug class into a build failure.

### P2 — Should fix: correctness, a11y, CI

**B15. Reduced-motion still staggers the hero underline sequence** ✔
The global reduce rule zeroes `animation-duration` but not `animation-delay` (`global.css:514`); `.hero__lead em::after` animations wait 600–1240 ms (`Layout.astro:114`) then apply instantly — a sequential pop-pop-pop under `prefers-reduced-motion`.
**Fix:** add `animation-delay: 0.01ms !important` (and `transition-delay`) to the reduce rule.

**B16. Focus ring disappears in Windows High Contrast / forced-colors** ✔
`:focus-visible` replaces `outline` with `box-shadow` (`global.css:135`); forced-colors mode strips box-shadows, leaving **no visible focus indicator** at all.
**Fix:** `outline: 2px solid transparent; outline-offset: 2px` alongside the box-shadow — forced-colors paints transparent outlines in system colors.

**B17. Small/missed touch targets** ✔
The coarse-pointer rule (`global.css:489`) fixes copy buttons and card refs but misses: the `<summary>` "Engineering detail" (~20 px tall), footer links, cert "view certificate" links, and the boot "skip intro" button. `masthead` shrinks to 10.6 px text under 720 px (`global.css:227`) — smallest text on the site on the highest-traffic element.
**Fix:** extend the coarse-pointer block; raise masthead floor to ≥12 px.

**B18. Signal rail sits ~8 px off (scrollbar width)** ✔
`left: max(calc((100vw - var(--maxw)) / 2 + 0.5rem), 0.9rem)` (`global.css:197`) — `100vw` includes the scrollbar, so the rail is shifted right relative to the actual content column on desktop.
**Fix:** use `100%` of a positioned ancestor or subtract `var(--scrollbar-w)` measured once in JS; simplest: position from the container's left edge via `calc((100% - var(--maxw)) / 2)` on a full-width wrapper (percentages exclude scrollbars).

**B19. Deploy workflow can cancel an in-flight production deployment** ✔
`concurrency: cancel-in-progress: true` (`deploy.yml:16`) — GitHub's own Pages starter uses `false` so a running deploy completes and the queued one follows.
**Fix:** `cancel-in-progress: false`.

**B20. The verify gate never runs on PRs/branches** ✔
`deploy.yml` triggers only on push to `main` — broken changes are caught *after* merge. This branch (`codex/…`) has never had CI run on it.
**Fix:** add a `pull_request` + feature-branch `push` workflow running `npm run verify` (build job only, no deploy). Cheap and removes the biggest process risk in the repo.

**B21. `check-build.mjs` blind spots** ✔
(a) path-form internal fragments (`/#projects`) are never checked against IDs — only bare `#…` (`:38-45`); (b) relative and own-domain-absolute asset URLs are skipped entirely (`:43`); (c) the `/\b(undefined|NaN)\b/` scan would false-fail on legitimate prose/script content (`:32`); (d) `id=` regex also matches inside inline JSON-LD/scripts (`:20`).
**Fix:** normalize all internal URLs (strip origin, resolve fragment against ID set); parse with a real HTML parser (`node:html` isn't available, but `parse5` is tiny — or accept regexes and narrow them).

**B22. Node/tooling friction** ✔
`engines` isn't enforced (no `.npmrc` `engine-strict=true`), so Node 20 users get a confusing Astro error after a successful install (exactly what happened on this machine — no nvm present, README assumes it). `node-version: 22.12.0` is hardcoded in CI, duplicating `.nvmrc`.
**Fix:** add `.npmrc` with `engine-strict=true`; use `node-version-file: .nvmrc` in the workflow.

**B23. Boot dismissal timing is duplicated magic** ✔
JS `setTimeout(…, 340)` (`BootIntro.astro:64`) must manually track the CSS `boot-wipe 320ms` (`global.css:239`).
**Fix:** listen for `animationend` on the wipe instead of a timer.

**B24. Certifications section is invisible to nav and scroll-spy** ✔
`nav[]` (`site.ts:42-48`) has no Certifications entry, so the section between Skills and Contact has no nav presence and the spy shows nothing/stale while scrolling through it.
**Fix:** either add it to the nav or fold certifications into another section (roadmap §10 suggests demoting the section — see "credibility sweep").

**B25. Sticky nav can render fully transparent (color-mix without fallback)** ✔
`.nav` background is only `color-mix(in srgb, var(--bg) 72%, transparent)` (`global.css:208`); the `@supports` fallback covers missing `backdrop-filter` but not missing `color-mix`. In the browser window that had `backdrop-filter` but not `color-mix` (e.g. Safari 15.4–16.1), the nav bar is transparent over content.
**Fix:** declare a plain `background: var(--bg)` (or rgba literal) first, then the `color-mix` value.

**B26. Unprefixed `mask-image` only** ✔
Blueprint-grid fade (`global.css:49`) and signal-rail mask (`:197`) use unprefixed `mask-image` with no `-webkit-mask-image` — browsers that only ship the prefixed property skip the mask (grid doesn't fade out; rail edges don't feather).
**Fix:** add the `-webkit-` twin (or accept the degradation deliberately — it's subtle).

**B27. `prefers-reduced-motion` is sampled once, never observed** ✔
`Layout.astro:86` and `Hero.astro:72` read `matchMedia(...).matches` at load only. Toggling the OS setting mid-session leaves the canvas, scramble, counters, and cursor effects running (or disabled) until reload.
**Fix:** listen to the media query's `change` event and start/stop the JS-driven effects accordingly.

**B28. Screen-reader roughness (grouped)** ✔
Decorative glyphs exposed to SR: "GitHub ↗" (`Nav.astro:15`) and "↗ repo" (`Projects.astro:98`) unlike everywhere else where glyphs are properly `aria-hidden` · no indication links open in new tabs · star counts announce as a bare number ("1") with the ★ hidden · the copy confirmation announces "Copy email copied to clipboard" (`Layout.astro:210` composes label + suffix awkwardly) · cert titles are `<p>` not headings · grid cards wrap the whole card in one `<a>`, producing paragraph-length link names · eyebrow "//" and "·" ornaments are read aloud by SRs.
**Fix:** wrap glyphs in `aria-hidden` spans + add `.sr-only` "(opens in new tab)" text; `aria-label="1 GitHub star"` on `.star`; rephrase copy-status; make cert titles `h3`; restructure grid-card links around the title with a stretched-link pattern; `aria-hidden` the ornament fragments.

**B29. Focus-visible coverage gaps** ✔
`<summary>` isn't in the `:where(a, button, input, [tabindex])` focus selector (`global.css:135`) so the details toggle gets the UA default ring, inconsistent with everything else. And because `<main tabindex="-1">` *does* match `[tabindex]`, activating the skip link draws the focus ring around the entire page body.
**Fix:** add `summary` to the selector; exclude `main` (`main:focus-visible { box-shadow: none }`).

**B30. More no-JS dead ends & SR text bugs (completeness pass)** ✔
(a) The contact **copy buttons render and take focus without JS but do nothing** — dead interactive controls in the no-JS baseline (`Contact.astro:21`); hide them under `html:not(.js)`. (b) The **protocols line and hero ticker read as one concatenated word** to screen readers — the separator dots are `aria-hidden` with no other separation ("UARTSPII²CCAN…", `Skills.astro:27`, `Hero.astro:40`); use commas in `.sr-only` text or make the separators plain text. (c) The **hero lead's authored spaces never render**: arrow segments output only the `label`, dropping the `" "` in `t` (`Hero.astro:19-20`) — visually masked by padding, but copied text and SR output read "hardware→firmware→custom Linux" unspaced. (d) **Print before scrolling (JS on) loses the trace dividers** — the print block resets `.reveal/.fade` opacity but not the JS-gated `stroke-dashoffset`/`scaleX`/gauge-width states (`global.css:433,120,395`). (e) The downloadable **CV PDF is untagged with empty Title/Author metadata** — blank tab title, poor SR support; re-export with metadata + tags.

**B31. Naming drift on the headline deployment** ✔
Hero key-spec says "Anti-Collision @ **Tata Steel**" (`site.ts:79`) while every other mention (About, flagship, experience, resume) says "**Tata Steel BlueScope**" — a different legal entity; precision matters on the single most-verifiable claim. Related accuracy nits: the "18 Projects" stat double-counts the voice subsystem the site itself labels "part of eOS" ~, and 8 of the 18 never render anywhere on the page.
**Fix:** "@ Tata Steel BlueScope" (it fits the spec row); rethink the stat per roadmap item 1.6.

## 4. Animation & interaction critique

The motion *infrastructure* is genuinely good — duration/easing tokens exist, the reveal system fails open per D-006, reduced-motion coverage is nearly complete, and the circuit/boot/LED ideas give the site a voice. The problems are discipline and consistency, not capability:

**4.1 Everything moves, so nothing means anything.** Seven infinite loops run simultaneously for the life of the page: title shimmer (×6 headings, 7 s), signal-rail node ping (2.2 s), LED breathe (2.4 s), pill pulse-dots (2 s), footer caret blink (1.06 s), scroll-cue nudge (2 s), circuit pulses (7–14 s with drop-shadow filters). Ambient motion should be reserved for *status* (the LED, the circuit current); attention motion should be *event-driven* (shimmer once when a heading enters view, replay on hover). This is the single biggest "themed template" tell on the site.

**4.2 The motion token scale leaks.** `--t-fast/--t/--t-slow/--t-draw` + three easings exist, but hardcoded values are scattered everywhere: 0.5 s (cursor glow), 0.35 s (card glow), 320 ms (boot wipe), 0.4 s (via-in), 1000 ms (count-up), 42 ms (scramble tick), 2–2.4 s (loops). Several transitions fall back to the UA default `ease`. One scale, no exceptions, is what makes a motion system feel engineered — fitting for this site's whole thesis.

**4.3 Inconsistent hover language across the same component family.** `pcard` lifts −3 px over 240 ms; `gcard` lifts −2 px over 160 ms with a different shadow; `cert` and `spec-card` don't respond at all; buttons translate via magnetic offset. And per **B2**, the card transitions don't actually run. Pick one hover grammar (lift distance, duration, glow) for all card-like surfaces.

**4.4 State changes that snap.** Hoverable spec rows (`dt`/leader/`dd` colors), the boot skip button, the `<details>` open/close (only the ▸ rotates), and the copy button (text swap changes the button width and shifts the row) all change state with zero transition — conspicuous next to the otherwise animated page.

**4.5 Choreography gaps.** Entrances fire per-container with hardcoded `--i` staggers that don't match actual column counts (`i % 4` for a grid that's 1–4 columns; `i % 3` for skills). The hero has no entrance at all — page pops fully rendered, then underlines + scramble fire on top. The lead-underline draw plays *behind* the boot overlay on first visits (finished before the user ever sees it — `Layout.astro:115` vs the 1.6 s overlay). The count-up finishes 300 ms after the gauge fill it accompanies.

**4.6 What's missing (best opportunities, all in roadmap §10):** CSS scroll-driven animations for the rail/reveals/counters (works with JS disabled — an *upgrade* to the D-006 contract, not just decoration); `@starting-style` hero power-on choreography in board-bring-up order; animated `<details>` via `interpolate-size`; arrival feedback when anchor-navigating to a section; a scroll cue that acknowledges scrolling.

## 7. Performance notes

Baseline is strong: ~410 KB total site, 5 KB JS, no third-party requests, hashed assets. The real issues:

1. **Font loading chain guarantees FOUT:** no `<link rel="preload">` for any of the three woff2 files, and they're discovered only after the external 35 KB CSS arrives (HTML → CSS → font, two sequential round trips). With `font-display: swap` and no metric-compatible fallbacks (`size-adjust`/`ascent-override`), the swap reflow is the site's only real CLS source. Fix: preload all three fonts (111 KB total is fine), add metric-tuned fallbacks, and consider inlining the CSS on this single-page site.
2. **`format("woff2-variations")` is the legacy-only syntax** — browsers that don't recognize it silently skip to system fonts. Use `format("woff2") tech("variations")` with the legacy string as a second `src` entry.
3. **Weight-range fat:** Inter ships 100–900 and JetBrains Mono 100–800, but the page uses ~400–700. Instancing the files to the used ranges saves ~30–40 % of the font payload.
4. **Idle CPU/GPU burn:** the six circuit pulses animate `stroke-dashoffset` under per-element `drop-shadow()` filters, full-viewport, forever — the most expensive standing cost on the page — plus the seven loops from §4.1 and a full-viewport gradient repaint per mousemove for the cursor glow (move a small pre-painted element with `transform` instead). The signal rail animates `height`/`top` (layout) per scroll frame — switch to `transform: scaleY/translateY`.
5. Assorted: spotlight writes aren't rAF-coalesced; `getBoundingClientRect` per pointermove; gauge animates `width`; `content-visibility: auto` on below-fold sections is free render savings; the sticky nav's `backdrop-filter` re-filters every frame (acceptable, but know it's paid).
